# Migration Plan: TanStack Start → Vite SPA on Vercel

## Why SPA (not Next.js)

Your UI, styling, components, Supabase calls, and AI assistant are already 100% client-compatible. The only true server code is:
- `src/server/assistant.ts` — a `createServerFn` that calls Lovable AI Gateway with `LOVABLE_API_KEY`.
- `src/integrations/supabase/auth-middleware.ts` and `client.server.ts` — never imported by UI.

A Vite SPA + one Vercel Serverless Function for the assistant is dramatically less work than a full Next.js port and keeps **zero UI changes**. Choosing Next.js would force rewriting every `createFileRoute` page, the root layout, head metadata, and routing primitives.

## What Changes

### 1. Build tooling
- Remove: `@tanstack/react-start`, `@lovable.dev/vite-tanstack-config`, `wrangler`, Cloudflare bits.
- Keep: `@tanstack/react-router` (works great in SPA mode), Tailwind v4, shadcn, Supabase, cobe, framer-motion.
- New `vite.config.ts`: standard `@vitejs/plugin-react` + `@tanstack/router-plugin/vite` in SPA mode + `@tailwindcss/vite`.

### 2. Entry points
- New `index.html` at project root with `<div id="root">` and `<script type="module" src="/src/main.tsx">`.
- New `src/main.tsx`: `createRoot(...).render(<RouterProvider router={router} />)`.
- `src/router.tsx`: keep as-is (already framework-agnostic).
- Delete `src/routes/__root.tsx` `shellComponent`/`HeadContent`/`Scripts` usage; replace with a normal layout component that renders `<Header /> <Outlet /> <Footer />`. Move `<title>`/meta into `index.html` defaults + per-route updates via a tiny `useDocumentHead` hook (or `react-helmet-async`).

### 3. Routes
- All 11 route files (`index, about, admin, assistant, auth, blog, community, contact, portfolio, profile, services`) keep their `createFileRoute(...)` declarations unchanged.
- `routeTree.gen.ts` continues to be auto-generated by `@tanstack/router-plugin`.

### 4. Server function → Vercel API route
- Move `src/server/assistant.ts` logic into `api/assistant.ts` (Vercel Serverless Function, Node runtime).
- Update `src/routes/assistant.tsx` to `fetch('/api/assistant', { method: 'POST', body: JSON.stringify(...) })` instead of `useServerFn`.
- Set `LOVABLE_API_KEY` in Vercel project env vars.

### 5. Supabase
- Browser client (`src/integrations/supabase/client.ts`) — unchanged, works in SPA.
- Delete `auth-middleware.ts` and `client.server.ts` (unused after assistant moves to `/api`).
- All auth, profiles, posts, projects, comments, likes, quotes already use the browser client → zero changes.

### 6. Vercel config
- `vercel.json`:
  ```json
  {
    "rewrites": [{ "source": "/((?!api/).*)", "destination": "/index.html" }]
  }
  ```
  This is the SPA fallback that fixes your 404 on `/assistant`, `/admin`, etc.
- Build command: `vite build`. Output: `dist/`.

### 7. GitHub + Vercel deploy
I cannot push to GitHub or configure Vercel from inside Lovable. You do this once:

1. In Lovable: top-right **GitHub → Connect** → create repo (e.g. `yemelink-web`).
2. On vercel.com → **Add New Project** → import that repo.
3. Framework preset: **Vite**. Build: `vite build`. Output: `dist`.
4. Env vars (Project Settings → Environment Variables):
   - `VITE_SUPABASE_URL` = `https://sjumahezjydnidthcnzx.supabase.co`
   - `VITE_SUPABASE_PUBLISHABLE_KEY` = (your anon key)
   - `LOVABLE_API_KEY` = (server-only, for `/api/assistant`)
5. Add domain `yemelink.vercel.app` (or it's auto-assigned).
6. Every Lovable change → auto-syncs to GitHub → Vercel auto-deploys.

## UI guarantee
Header, Footer, Globe3D, all 11 routes, Tailwind tokens, animations, glassmorphism, fonts — all rendered by the same React components in the same order. Pixel output is identical.

## Risks / caveats
- Initial paint becomes client-rendered (no SSR). SEO meta tags injected via `index.html` + per-route hook are fine for a portfolio site; if you later want SSG for blog/portfolio SEO, that's a separate follow-up.
- The `assistant` page loses TanStack `useServerFn` ergonomics → replaced with plain `fetch` + a tiny error/loading state (already there).
